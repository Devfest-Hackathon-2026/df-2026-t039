# 既存の旅行プランを具体化・変更する

## 手順

1. `get_current_trip` で現在のプランを取得する。会話の記憶ではなく、この結果を正とする。
2. 変更したいことを確認する。はっきりしない場合は、未定の項目（日程、何日目か未定の予定、時刻、予算など）から1〜2個を挙げて聞く。
3. 変更の影響を確認して伝える。
   - 日数を減らす場合、範囲外になる日の予定をどうするか（移動・削除）を先に決める。
   - 予定を追加する場合、同じ日の時刻の重なりや移動時間に無理がないか確認する。
   - 新しい場所が必要なら、Google Maps の情報に基づいて提案する。
4. ユーザーが合意した内容だけを保存する。
   - 基本情報は `update_trip_preferences`。
   - 旅程は `get_current_trip` の内容を元に、変更箇所以外を残したまま `update_itinerary` で全体を保存する。
   - 場所を入れるときは `list_suggested_places` または `list_saved_places` で id を確認する。
5. ツールが `ok: false` を返したら、理由をユーザーに伝えて進め方を確認する。
6. 保存できたら、何を変えたかを短く伝える。

## してはいけないこと

- 行き先や予定を海外に変更しない。海外を希望されたら国内旅行のみ対応と伝え、国内の代わりの候補を挙げる。
- ユーザーが変更を求めていない予定を消したり並べ替えたりしない。
- 推測した値で未定の項目を埋めない。
- プランを確定（予定済み）にしない。確定はユーザーが画面で行う。
